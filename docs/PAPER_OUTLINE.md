## 0. 标题与定位

**候选标题**

1. *Does Low-Light Enhancement Help Object Detection? A Systematic Study on ExDark*
2. *Beyond PSNR: How Low-Light Enhancement Affects Object Detection*
3. 中文暂定：《低照度增强对暗光目标检测的影响：一项系统性研究》

**一句话贡献**：目前低照度增强普遍被当作检测的前处理，但缺乏系统评估。我们发现——
**除 CLAHE 外，几乎所有增强都拖累检测，且掉点的主导因素是域偏移而非画质**；
亮度与检测性能呈强负相关（r = −0.971）。域适配后 CLAHE 甚至转正，说明"增强本身有益、错在先处理没同步重训检测器"。

**这不是一篇"提出更好的增强方法"的论文**，而是一篇"测量与解释"的论文。
我们自己的 INDNet 作为参评方法之一，**不宣称最优**。

### §3 Experimental Setup（写细，审稿人靠这节判断可信度）

- **数据**：ExDark，7362 张，12 类，23710 个框；尺寸混合（640×480 / 640×427 / 507×338…），禁用固定尺寸 ✅
- **方法**：10 种输入，参数全部公开（CLAHE 的 clipLimit=2.0 / tile=8×8；MSR 的 σ=15/80/250；MSRCR α=125 β=46）✅
- **统一口径**（重要，必须写）：所有增强在长边 ≤1024px 上进行再插值回原尺寸；检测器内部缩到 640 ✅
- **检测器**：YOLOv8n（COCO 预训练），conf=0.01 / IoU=0.5，mAP@0.5 🟡（第二检测器待补）
- **两个协议**：
  - 协议 I（冻结）：检测器不动，只换前处理
  - 协议 II（域适配 / A2）：表 A = 每条管线各训一个检测器；表 B = 统一用原图训的检测器测其他管线
- **统计判据（必须声明）**：7362 张图时 mAP 采样噪声约 **±0.005**，小于该值判为无差异；
  LOL-v1 上 PSNR 的标准误约 **±0.5 dB**，小于该值不宣称优劣 ✅

### §4 Systematic Evaluation

- **Table 1**：10 种输入的 mAP（冻结协议）✅
- **Fig. 2**：亮度 Y vs mAP 散点 ✅（r = −0.971，去掉 MSRCR）
- **Fig. 3**：分类型 mAP 热力图 ✅ —— 纹理类（cat/dog/bottle/cup）掉得多，轮廓类（bicycle/table/boat）掉得少
- 关键表述：**"提亮越多，掉得越多"是连续单调的，不是个别方法失效**

### §5 Domain Shift Decomposition（本文核心）

- **Table 2**：表 A / 表 B / 拆解三项 ✅
- 定义清楚：总计 = 质量分量 + 域偏移分量（Δ_B = Δ_A + 域偏移）
- **Table 3**：域适配本身带来的增益（0.5338 → 0.6819，**+0.1481**）✅

### §6 Discussion

1. **亮度上限**：Y ≤ 55 是安全区（原图 37、CLAHE 53 都不掉点；Gamma 78 开始掉）✅
2. **为什么是域偏移**：COCO 预训练检测器的特征对输入的光照统计敏感；过度增亮 + 对比度/梯度放大改变了分布 ✅
3. **色偏是第二因素**：MSRCR 是唯一例外（Y 仅 106 但 mAP 最低，色彩丰富度 62.1 vs 其他 30–47）✅
4. **部署含义**：换前处理必须重训检测器；否则白掉 0.02–0.06，且这个损失与画质无关 ✅

### §7 Limitations（主动写，别等审稿人问）

- 单一数据集（ExDark）、单一场景族（夜景）
- 主结果为单一检测器（YOLOv8n）🟡
- LOL-v1 测试集仅 15 张，增强指标的标准误较大 ✅（已声明）
- 增强方法与检测器均为 2023–2024 年主流，未覆盖最新 transformer 检测器

### §8 Conclusion

一句话收束：**低照度增强不是一个"免费"的检测前处理**；收益取决于亮度控制的克制程度，以及检测器是否同步域适配。

## 4b. 双因子模型（本文最有分量的分析，取代原来单一的"亮度决定论"）

加入 Retinexformer 之后，原本"亮度解释一切"的说法**必须修正** ——
它和 INDNet 的亮度几乎相同（89.8 vs 90.0），mAP 却差 0.025。这反而让分析更扎实：

```
mAP ≈ f(亮度) + g(画质)      拟合：mAP = −0.00161·Y + 0.6281（11 点，去 MSRCR）
```

| 因子 | 证据 | 量级 |
|---|---|---|
| **① 亮度（主导）** | Y vs mAP：r = **−0.954**，Spearman −0.909；暗部占比 Spearman **+0.955** | 跨越 Y=37→160，mAP 掉 0.18 |
| **② 画质（残差项）** | 同等亮度下的残差：Retinexformer **+0.0370** > 残差 U-Net +0.0150 > INDNet +0.0126 > Zero-DCE −0.0021 | 最大 ±0.037 |
| ③ 色偏（离群） | MSRCR：Y 仅 106 却 mAP 最低（0.266），色彩丰富度 62.1 vs 其余 30–49 | 单独讨论 |

**解读**：亮度是"总闸门"，决定掉点的量级；画质决定在同等亮度下能挽回多少。
Retinexformer 的 PSNR（25.16）显著高于我们（21.13），残差也相应更大（+0.037 vs +0.013）——
**这条正好用上了 LOL-v1 的 PSNR 排名，把"画质"这一因子量化了**。

⚠️ 写作红线：不要说"亮度决定一切"。正确表述是
"亮度解释了绝大部分方差（r² ≈ 0.91），但同等亮度下仍存在由画质决定的系统性偏差"。

## 7. 写作红线（避免被打）

1. **不要说"我们的方法最好"** —— PSNR 21.13 低于 Retinexformer 25.16，且三个变体的 PSNR 差异在噪声内
2. **不要宣称解耦成立了** —— 实测光照图 L 塌缩成常数（std ≈ 0），只能写"辅助分解头"
3. 所有"显著"必须配上判据（mAP 用 ±0.005，PSNR 用 ±0.5 dB）
4. 域适配的增益（+0.1481）要强调是**协议差异**，不是"我们提升了检测"
5. 表 A 的 `original` 只用本轮 0.6819，**不要混用历史记录的 0.6848**
