# 实施路线图：INDNet 从零到投稿

总预算：**约 9–12 周**（按每天投入 3–4 小时估算；全职投入可压缩到 5–6 周）

每个阶段都设定了**通过标准（Checkpoint）**。达不到就不要进入下一阶段——
科研里最贵的成本不是做错，而是在错误的管道上继续往前跑。

---

## P0 · 环境与数据（1–2 天）

### 要做的事
1. 建隔离虚拟环境，装依赖
2. 下载 LOL-v1（必需）、LOL-v2-real（必需）、ExDark（必需）
3. 跑通 `scripts/check_data.py`，确认目录结构正确

### 通过标准
- `check_data.py` 报告：LOL-v1 训练 485 对 / 测试 15 对全部就位
- ExDark 图像数 7,363、标注文件可被解析
- 随意打开 3 组 (low, high) 图，肉眼确认是同一场景的配对照

### 风险
谷歌 Drive 有每日配额。**优先走 Kaggle / OpenXLab 镜像**，别一开始就死磕官方链接。

---

## P1 · 基线复现与评测链（3–5 天）⚠️ 最关键的一步

### 要做的事
1. 下载 **Retinexformer 官方代码与预训练权重**，在 LOL-v1 eval15 上复现它的指标
2. 用 Retinexformer 的输出目录，跑 `utils/metrics.py`，对比论文报告值
3. 再复现一个轻量基线（SCI 或 Zero-DCE++），验证管道通用性
4. 确定并**锁定 PSNR/SSIM 的计算约定**（RGB 直接算 vs 只算 Y 通道）

### 通过标准
- 复现 Retinexformer 在 LOL-v1 上 **PSNR ≥ 25.0、SSIM ≥ 0.84**（允许 ±0.2 误差）
- 若偏差超过 0.5 dB，**必须查明原因再继续**（通常是：颜色空间约定不同、图像保存时被 JPEG 二次压缩、或归一化范围 [0,1] / [0,255] 不一致）

### 为什么这步不能跳
你的所有对比数字都出自这条管道。管道错了，后面 8 周的实验全部作废。
这 3–5 天是整个项目性价比最高的投入。

---

## P2 · 主方法 INDNet 实现（7–10 天）

### 要做的事
按依赖顺序逐步搭建，**每加一个模块就单独训练一轮**，确认它有效：

| 顺序 | 模块 | 观察点 |
|---|---|---|
| 1 | 基础 U-Net 骨干（无解耦） | 作为消融的 baseline 行 |
| 2 | ＋光照估计分支 | 光照图应呈现平滑的空间渐变 |
| 3 | ＋噪声感知分支 | 噪声图应主要集中在暗区高频 |
| 4 | ＋光照平滑损失 | 抑制光照图伪影 |
| 5 | ＋噪声一致性损失 | 暗区噪声明显减少 |

### 通过标准
- 完整模型在 LOL-v1 上 100 epoch 内训练不出现 NaN、不显存溢出
- 指标（PSNR 或 LPIPS）**至少优于你的 U-Net 基线**
- 三张分解图（L / R / N）可视化后符合物理直觉

### 注意
不要一次性写完 5 个模块再训练。分步加、分步验证，
这样消融表天然就是现成的，而且出错时能立刻定位。

---

## P3 · 完整实验（15–20 天）

### 要做的事
按 `docs/EXPERIMENT_PLAN.md` 填满四张表：

1. **主表**：与 15 个基线在 LOL-v1 / LOL-v2-real 上对比
2. **消融表**：拆模块 + 损失权重敏感性
3. **应用表**：ExDark 上接 YOLOv8，报告 mAP 提升
4. **效率表**：参数量 / FLOPs / 推理时间 / 显存

### 通过标准
- 四张表无空缺行
- 主表上你的方法在**至少一项指标**上取得最优，或次优但参数量明显更小
- 应用表上，INDNet 增强后的 mAP **高于**原图直接检测、且不劣于其他增强方法

### 降低风险的建议
- 每填完一张表就存一份快照（`experiments/*/snapshot`），避免重跑
- 视觉对比图尽早做（Fig.3 / Fig.4），它能帮你发现指标看不出的问题

---

## P4 · 论文写作（15–20 天）

### 写作顺序（不要从 Introduction 开始写）

1. **Method**（你刚做完，记忆最新）
2. **Experiments**（表格已在手，边写边补文字解释）
3. **Introduction**（此时你最清楚自己的贡献是什么）
4. **Related Work**（最后写，避免过早定型叙述框架）
5. **Abstract / Conclusion**（收尾）

### 五章结构

| 章节 | 核心内容 | 篇幅 |
|---|---|---|
| 1. Introduction | 暗光退化双病因 → 现有方法不足 → 三条贡献 | 1–1.5 页 |
| 2. Related Work | Retinex 方法 / 低照度增强 / 暗光检测，各一段 | 1–1.5 页 |
| 3. Method | 总览图 → 两分支细节 → 损失函数 | 3–4 页 |
| 4. Experiments | 数据集与实现细节 → 四张表 → 视觉结果 | 4–5 页 |
| 5. Conclusion | 结论 + 局限性 + 未来工作 | 0.5 页 |

### 通过标准
- Method 章节的每张图，都能用一句话说清"这张图想证明什么"
- 三条贡献在 Introduction 末尾和 Conclusion 开头**一字不差地重复出现**
- 全文用词统一（统一叫 illumination map / reflectance map / noise map）

---

## P5 · 投稿与返修（投稿后 1–8 个月）

### 要做的事
1. 投稿前自查（见文末清单）
2. 按 PAA 要求准备 **Cover Letter** 与 **代码开源仓库**
3. 提交；准备 1–8 个月等审稿意见
4. 返修时逐条回应，**不要回避任何一条**，即使不同意也要给出理由

### 通过标准
- 代码仓库可被陌生人按 README 一键跑通
- 所有实验数据、划分方式、随机种子均已公开

---

## 投稿前自查清单

- [ ] 代码已开源（GitHub），含 README、依赖版本、预训练权重
- [ ] 数据划分明确写出，且**与基线论文的划分一致**
- [ ] PSNR/SSIM 的**计算约定在文中明确声明**（RGB 还是 Y 通道）
- [ ] 对比的基线覆盖 2023–2024 年的 SOTA（Retinexformer / RetinexMamba / HVI）
- [ ] 补了 LOL-v2-real 或 LSRW 的跨数据集结果（应对"测试集仅 15 张"的质疑）
- [ ] 消融实验覆盖**每一个**提出的组件和损失项
- [ ] 所有图表在灰度打印下仍可区分
- [ ] 参考文献格式符合 PAA 要求（Springer 数字顺序制）
- [ ] 查重通过，语言已润色
- [ ] 所有作者的贡献与署名已确认
